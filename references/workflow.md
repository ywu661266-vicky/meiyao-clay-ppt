# 工作流详解（三步确认法）

核心目的：**用最少的出图额度，换用户最满意的结果。** 每次出图前先想清楚"用户要看到什么才能判断对错"。

---

## Phase 0 · 收集素材

一次问清，不要挤牙膏：

1. **内容**：主题 + 每页要讲什么。
   - 有文件就先读文件（`.md` / `.docx` / `.pptx` / `.html`），从里面提取真实内容，不编造。
   - 用户只给关键词时，先列出拟定的页目录（如：封面 / 目录 / 6 个场景 / 总结），**让用户确认页数和顺序**，再动图。
2. **人物**：让他用一句话说清形象，例如"短发、发箍、一个小啾啾、戴眼镜、穿裙子"。
3. **配色**：默认深蓝；一句"要换配色吗"即可，别展开长篇选项。

---

## Phase 1 · 角色锚点（1 张）

- 生成 1 张 `1024x1024`，只做**人物半身**，中性灰底。
- **当场给用户看**，并逐条列出"我核对的特征"（发型/发饰/眼镜/服装），让他一眼确认。
- 不合格 → 按反馈改特征重出 1 张；**永远单张迭代，不批量。**

**话术模板：**
> 这版人物特征对不对？我核对：短发 ✅ 发箍 ✅ 眼镜 ✅ 裙子 ✅。对的话我出封面，不对你说哪要改，我重出。

---

## Phase 2 · 封面（1 张）

- 生成 1 张 `1024x576`，**把主标题烘进图**（整页效果最直观）。
- 给用户看时明确说：**"这一张代表整页效果：人物 + 文字 + 场景。"**
- 用户确认 OK → 进入批量；不 OK → 改，仍单张迭代。

**为什么封面要带字：** 用户判断"对不对"靠的是**完整一页的观感**，光给人物看不出效果；带字带场景，一次就能定调。

---

## Phase 3 · 批量内页

页数结构（按需裁剪）：

| 页型 | 数量 | 出图内容 |
|------|------|----------|
| 封面 | 1 | 人物 + 主标题铭牌（可烘字） |
| 目录 | 1 | 编号卡/文件夹，左侧铭牌留空 |
| 内容页 | N | 每页一个知识点，左侧铭牌留空 |
| 总结 | 1 | 奖杯/对钩 + 左侧铭牌留空 |

- 全部 `size: "1024x576"`。
- 每页 prompt 复制同一段人物 + 风格描述；只改主题道具。
- 内页统一 `No written words`，文字留给脚本叠加（保证可编辑）。

---

## Phase 4 · 合成 PPTX

1. 写 `slides.json`：每页 `image` 路径 + `title` + `bullets` + `notes`。
2. 运行：
   ```bash
   python scripts/build_pptx.py --config slides.json --out "主题_黏土风.pptx"
   ```
3. 校验：页数、16:9 尺寸、文字无溢出错位、右下角无水印冲突。

---

## Phase 5 · 交付

- `present_files` 交付 `.pptx` + 封面/角色预览图。
- 附一句：页数 / 主题 / 配色 / 文字可编辑说明。

---

## 常见翻车与对策

| 现象 | 原因 | 对策 |
|------|------|------|
| 一整套图全废 | 没先确认人物就批量 | 严格执行 Phase 1 单张确认 |
| 人物每页长得不一样 | prompt 里人物描述被改写/省略 | 逐字复制同一段人物描述 |
| 用户觉得"看不到效果" | 只给了无字人物图 | 封面一定带中文标题 + 场景 |
| 文字压在水印上 | 版式没避开右下角 | 文字统一放左/上，右下留空 |
| 页数不对/顺序乱 | 没先确认目录 | Phase 0 先定页目录再出图 |
